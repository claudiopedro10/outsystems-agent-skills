# Revisão do repositório — 24 de novembro de 2026

## Objetivo

Deixar o uso automático para um desenvolvedor novo: instalar as skills com um
prompt, mandar a demanda (módulo, ação, o que fazer) e o agente escolher sozinho
a skill certa, começar o trabalho e perguntar quando faltar informação.

## Verificação de mesa do roteamento

Feita pela leitura das descrições antigas e novas, como um agente faria ao
escolher uma skill. **Não é execução em agente real**; os mesmos pedidos estão
em [casos de roteamento](../evaluation.md#casos-de-roteamento) para execução.

| Pedido | Antes (descrições em inglês) | Depois |

| “Extrai a validação duplicada sem mudar as assinaturas.” | developer | developer → Refatorar |

Antes, cinco dos dez pedidos tinham duas ou mais skills plausíveis. Depois, só o

## Convivência com a skill oficial

Conferido no repositório oficial, commit `91c9e09`: a pasta continua
`servicestudio-mcp-oml`. Dois pontos dela batem com a regra deste repositório:

- a referência de ferramentas descreve como chamar o servidor MCP por shell e
  `curl` (transporte HTTP);
- os guias de setup sugerem `netstat` para descobrir a porta.

Por isso, as sete skills e a regra do AGENTS.md dizem que a skill oficial é só
referência, que o agente não deve chamar o MCP por shell, `curl` ou script e que,
em conflito, valem a `outsystems-developer` e a regra de não usar terminal. O
caso E15 da avaliação cobre isso com a skill oficial instalada.

A descrição da skill oficial fala da Model API e do arquivo `.oml`, não de
corrigir bugs ou criar funcionalidades, então ela tende a não competir com a
`outsystems-developer` na escolha da porta de entrada. Isso não foi testado em
agente real.

A escrita pelo MCP continua Beta: confira as mudanças no Compare and Merge do
Service Studio antes de aceitar.

## Teste ao vivo e correção do registro do MCP

Em 24/11/2026, no VS Code com Claude Code e o Service Studio 11.55.98 (módulo
`claudio_cs`), o prompt de instalação carregou as 8 skills e criou o CLAUDE.md.
Sem o MCP registrado, o agente parou e pediu para conferir o Service Studio, sem
usar terminal. O registro manual do `.mcp.json` saiu incompleto em dois
computadores (faltava o começo do JSON). Depois de corrigido, `/mcp` mostrou
`outsystems` como Connected e o agente leu o módulo com `listOpenModules` e
`getDataModel`.

Correção: o prompt passou a trazer o endereço na primeira linha e a mandar o
agente criar e validar o arquivo de configuração MCP do host. Foram adicionados
arquivos prontos em `config/` para o registro manual. Caso R12 na avaliação.

Num segundo computador, o Claude Code criou `.vscode/mcp.json` (formato do
Copilot) por estar dentro do VS Code, e deixou o arquivo sem salvar. O prompt
passou a dizer que o formato depende do agente, não do editor, e a exigir que o
agente salve, releia e diga qual arquivo criou.
