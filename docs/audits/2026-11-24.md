# Revisão do repositório — 24 de novembro de 2026

## Objetivo

Deixar o uso automático para um desenvolvedor novo: instalar as skills com um
prompt, mandar a demanda (módulo, ação, o que fazer) e o agente escolher sozinho
a skill certa, começar o trabalho e perguntar quando faltar informação.

## Mudanças

| Tema | Antes | Depois |
| --- | --- | --- |
| Skill oficial do O11 MCP | Pré-requisito em README, docs e nas sete skills | Opcional. As skills usam as ferramentas que o servidor MCP do Service Studio anuncia |
| Conexão com o MCP | Proibia varrer portas, mas não citava terminal | Todas as skills proíbem PowerShell, cmd, bash, curl, `Invoke-WebRequest`, `netstat` e scripts para testar ou se conectar ao MCP; na primeira falha, param e pedem para conferir o Service Studio (caso E15) |
| Descrição da `outsystems-developer` | “Start here for everyday…” | Porta de entrada padrão para **qualquer** tarefa OutSystems, mesmo sem nomear a skill |
| Descrições dos especialistas | “Specialist review of…”, sem dizer quando **não** usar | Cada uma diz o assunto e termina mandando bugs, refatorações e funcionalidades do dia a dia para `outsystems-developer` |
| `outsystems-troubleshooting` | Disputava qualquer bug com o fluxo Troubleshoot da `outsystems-developer` | Só investigação aprofundada com logs e hipóteses, pedido explícito ou quando a `outsystems-developer` não isola a causa |
| README | Começava por um aviso de pré-requisitos e seis especialistas | Começa por “Como começar” com o prompt de instalação; depois só mandar demandas |
| Idioma | Inglês | Português do Brasil, com nomes técnicos do OutSystems em inglês; a licença MIT continua no texto original |
| Fluxos | Troubleshoot, Refactor, Implement | Investigar, Refatorar, Implementar |

Os nomes das pastas e das skills (`outsystems-developer` etc.) não mudaram, para
não quebrar instalações existentes.

## Verificação de mesa do roteamento

Feita pela leitura das descrições antigas e novas, como um agente faria ao
escolher uma skill. **Não é execução em agente real**; os mesmos pedidos estão
em [casos de roteamento](../evaluation.md#casos-de-roteamento) para execução.

| Pedido | Antes (descrições em inglês) | Depois |
| --- | --- | --- |
| “O modal não fecha depois de aprovar.” | Ambíguo: developer ou troubleshooting (ou enduser) | developer → Investigar |
| “Cria uma ação para cancelar o pedido em rascunho.” | Provável developer; core competia (“domain services”) | developer → Implementar |
| “Extrai a validação duplicada sem mudar as assinaturas.” | developer | developer → Refatorar |
| “A cidade antiga continua selecionada ao trocar o Estado.” | Ambíguo: developer ou enduser | developer → Investigar |
| “Melhora essa ação.” | developer, com pergunta | developer, com pergunta |
| “O ERP dá timeout e às vezes duplica o pedido.” | Ambíguo: foundation, troubleshooting ou developer | foundation (ou developer acionando a Foundation) |
| “Um usuário vê pedidos de outro trocando o OrderId.” | Ambíguo: security ou troubleshooting | security |
| “Tem um ciclo Orders_UI -> Orders_CS -> ERP_IS.” | architecture | architecture |
| “Analisa os logs do Service Center; tenho três hipóteses.” | troubleshooting | troubleshooting |
| “Revisa a jornada de checkout: loading, vazio e erro.” | enduser | enduser |

Antes, cinco dos dez pedidos tinham duas ou mais skills plausíveis. Depois, só o
caso do ERP tem duas respostas, e as duas levam à mesma especialidade.

## Validação

- **Aprovado:** os nove testes unittest (metadados, links e âncoras,
  empacotamento independente).
- **Revisado manualmente:** remoção da exigência da skill oficial, regra de não
  usar terminal nas sete skills, links internos com âncoras em português.
- **Não executado:** casos E01–E15 e R01–R11 em agentes reais; instalação pelo
  prompt em cada host; comportamento ao vivo em O11/ODC.

## Ponto de atenção

Sem a skill oficial, o agente depende das descrições das ferramentas que o
servidor MCP anuncia para ler e, principalmente, escrever no modelo. Se alguma
escrita pelo MCP se comportar mal, instalar a skill oficial do
[repositório da OutSystems](https://github.com/OutSystems/outsystems11-mcp)
continua sendo uma opção.
